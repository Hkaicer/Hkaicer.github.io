Behavioral Threat Detection for High-Volume Security Operations

An end-to-end, open-source pipeline that learns normal Windows/Active Directory behavior, detects anomalous activity without predefined signatures and produces analyst-ready MITRE ATT&CK context.

lab-validated production anomaly confirmed by SOC sanitized — no internal details

01 · context & problem

Signatures miss what they haven't seen

Security Operations Centers rely heavily on signatures and predefined rules. These mechanisms remain essential for known threats, but they can miss previously unseen or context-dependent activity. In a telecom environment, the challenge is amplified by high event volumes — on the order of ten thousand events per second — strict confidentiality requirements and analyst workload.

The objective: design a complementary behavioral-detection layer that learns normal activity from unlabeled telemetry, identifies anomalous host behavior and translates findings into actionable context for SOC analysts — without sending raw logs outside the organization.

my role

I owned the project from requirements and architecture through implementation, attack simulation, result analysis and documentation — the telemetry pipeline, feature-engineering strategy, model ensemble, orchestration workflow and analyst-facing outputs.

02 · architecture

From raw telemetry to analyst-ready context

  • Windows Security and Sysmon telemetry collected through Winlogbeat.
  • Logstash processing and Elasticsearch storage with Kibana visualization.
  • Five-minute host-level activity windows engineered from volume, diversity, ratio, temporal and novelty signals.
  • Unsupervised ensemble combining Isolation Forest, LOF, ECOD and HBOS — global, local and distribution-based views of abnormality.
  • Apache Airflow for recurring execution and MLflow for experiment and artifact tracking.
  • Local LLM layer for concise explanations and MITRE ATT&CK mapping — an investigation aid, never an autonomous verdict.
  • Dashboard, email notification and structured incident PDF for SOC consumption.

03 · validation

Replayed attacks, real anomalies

The pipeline was evaluated in an isolated Active Directory lab with replayed attack scenarios including Kerberoasting and forged Kerberos-ticket behavior. It flagged the relevant time windows on the correct host without relying on attack signatures — at the moment the attacks were launched.

An earlier version of the approach was also applied to real production-network data; a high-scoring anomaly was investigated and confirmed by the SOC team. Conversely, a high-scoring window on a domain controller turned out to be a legitimate service restart — a documented operational false positive that shaped the human-review workflow.

what the project proved
  • Behavioral features can complement rule-based detection.
  • An ensemble provides multiple views of abnormality: global, local and distribution-based.
  • Explainability and analyst context are as important as the anomaly score.
  • False positives are expected and must be handled through operational context and human review.
  • Data sovereignty can be preserved with local processing and a locally hosted language model.

04 · limitations — stated, not hidden

What this system does not claim

limitations
  • The final lab implementation was not benchmarked publicly at the operator's full event volume.
  • Without reliable labels, classical precision, recall and AUC metrics are not sufficient for evaluation.
  • Five-minute windows may miss low-and-slow attacks spread over long periods.
  • The lab used limited hosts and telemetry sources compared with a full enterprise environment.
  • The LLM explanation is an investigation aid, not an autonomous incident verdict.

A score measures deviation from learned behavior, not malicious intent. Every flagged window is a lead for the analyst — enriched with operational context, recent changes and service history — never a conclusion.
