Behavioral Threat Detection for High-Volume Security Operations

An end-to-end, open-source pipeline that learns normal Windows and Active Directory behavior, catches anomalous activity without predefined signatures, and produces analyst-ready MITRE ATT&CK context.

lab-validated finding confirmed by SOC sanitized · no internal details

01 · context & problem

Signatures miss what they haven't seen

SOCs rely heavily on signatures and predefined rules. Those stay essential for known threats, but they miss what is new or context-dependent. In a telecom environment the pressure is higher still: very high event volumes (around ten thousand per second), strict confidentiality, and heavy analyst workload.

The goal was a complementary behavioral layer that learns normal activity from unlabeled data, flags anomalous host behavior, and turns findings into actionable context for analysts, all without sending raw logs outside the organization.

my role

I owned the project end to end: requirements, architecture, implementation, attack simulation, result analysis and documentation. That covered the data pipeline, feature-engineering strategy, model ensemble, orchestration and the analyst-facing outputs.

02 · architecture

From raw activity to analyst-ready context

Hover or tap a stage to see its role, or run the full cycle.

  • event
  • 5-min window
  • scored window
  • alert
  • Windows Security and Sysmon activity collected through Winlogbeat.
  • Logstash processing and Elasticsearch storage with Kibana visualization.
  • Five-minute host-level windows built from volume, diversity, ratio, temporal and novelty signals.
  • Unsupervised ensemble combining Isolation Forest, LOF, ECOD and HBOS for global, local and distribution-based views of abnormality.
  • Apache Airflow for recurring runs and MLflow for experiment and artifact tracking.
  • Local LLM layer for concise explanations and MITRE ATT&CK mapping. It aids investigation and never issues an autonomous verdict.
  • Dashboard, email notification and structured incident PDF for the SOC.

03 · validation

Replayed attacks, real findings

The pipeline ran in an isolated Active Directory lab against replayed attacks, including Kerberoasting and forged Kerberos tickets. It flagged the right time windows on the right host with no signatures, exactly when each attack was launched.

The approach was also applied to real production traffic. A high-scoring finding on the operator's F5 firewall logs was investigated and confirmed by the SOC team. A separate high-scoring window on a domain controller turned out to be a legitimate service restart, a documented false positive that shaped the human-review step.

what the project proved
  • Behavioral features can complement rule-based detection.
  • An ensemble gives several views of abnormality: global, local and distribution-based.
  • Explainability and analyst context matter as much as the score.
  • False positives are expected and handled through operational context and human review.
  • Data sovereignty holds with local processing and a locally hosted language model.

04 · limitations, stated not hidden

What this system does not claim

limitations
  • The final lab build was not benchmarked publicly at the operator's full event volume.
  • Without reliable labels, classical precision, recall and AUC are not enough for evaluation.
  • Five-minute windows may miss slow attacks spread over long periods.
  • The lab used limited hosts and sources compared with a full enterprise.
  • The LLM explanation is an investigation aid, not an autonomous verdict.

A score measures deviation from learned behavior, not intent. Every flagged window is a lead for the analyst, enriched with operational context and service history, never a conclusion.
